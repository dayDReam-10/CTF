# TEA

## 算法原理

### 1. 数据拆分

64位（8字节）的明文被平均拆成两个32位的半块：

我们假设`v0`为左半块，`v1`为右半块，如`0x89ABCDEF89ABCDEF`被拆成`0x01234567` (左半块 `v0`)和`0x89ABCDEF`(右半块 `v1`)

### 2. 密钥拆分

128位（16字节）的密钥被拆成4个32位子密钥：

`k0, k1, k2, k3`(同上拆分)

### 3. 轮函数与累加器

算法执行 32轮 迭代，每一轮都引入一个累加器 `sum`，从 0 开始，每轮固定增加一个魔法常数 `delta = 0x9E3779B9`

### 4. 轮运算

每一轮按顺序执行以下两步：

**步骤一：** 用右半块 `v1` 加部分密钥搅动左半块 `v0`

```text
v0 += ((v1 << 4) + k0) ^ (v1 + sum) ^ ((v1 >> 5) + k1)
```

分解来看，这个表达式由三个部分异或而成：

- `(v1 << 4) + k0` —— 将 v1 左移4位后与第一个子密钥相加（非线性扩散）
- `(v1 + sum)` —— v1 与当前轮次累加器相加（引入轮次变量）
- `(v1 >> 5) + k1` —— 将 v1 右移5位后与第二个子密钥相加（互补移位）

三个结果异或后，再加到 `v0` 上。

**步骤二：** 用更新后的左半块 `v0` 加部分密钥搅动右半块 `v1`

```text
v1 += ((v0 << 4) + k2) ^ (v0 + sum) ^ ((v0 >> 5) + k3)
```

逻辑完全一样，只是换成了用 `v0` 去更新 `v1`，使用的子密钥也换成了 `k2` 和 `k3`

加密模板如下

```c
#include <stdint.h>

void tea_encrypt(uint32_t *v, uint32_t *k) {
    // 第一步：准备两个盒子
    uint32_t v0 = v[0], v1 = v[1];
    // 准备四个密钥盒子
    uint32_t k0 = k[0], k1 = k[1], k2 = k[2], k3 = k[3];

    // 第三步：轮次标记
    uint32_t sum = 0;
    uint32_t delta = 0x9E3779B9;

    // 第四步：重复搅拌32轮
    for (int i = 0; i < 32; i++) {
        sum += delta;                                              // 更新轮次
        v0 += ((v1 << 4) + k0) ^ (v1 + sum) ^ ((v1 >> 5) + k1);   // 搅拌v0
        v1 += ((v0 << 4) + k2) ^ (v0 + sum) ^ ((v0 >> 5) + k3);   // 搅拌v1
    }

    // 把结果放回原数组
    v[0] = v0;
    v[1] = v1;
}
```

### 解密原理

由于Feistel网络的可逆性，解密过程完全复用加密代码，只需做两处修改：

- 将 `sum` 的初始值设为 `32 × delta = 0xC6EF3720`（加密结束时的值）
- 每轮先将 `sum` 减去 `delta`（即逆向累加）
- 轮内运算顺序颠倒：先更新 `v1`，再更新 `v0`（因为加密时最后更新的是 `v1`）

说人话就是模拟结束量，完全反过来一次

学习完以上知识我们可以看到，要逆向TEA我们需要密钥流，密文即可

一般而言，解密脚本如下：

```c
#include <stdio.h>
#include <stdint.h>

// TEA 解密函数
// v: 密文数组（8字节，解密后变成明文）
// k: 密钥数组（16字节）
void tea_decrypt(uint32_t *v, uint32_t *k) {
    uint32_t v0 = v[0], v1 = v[1];
    uint32_t k0 = k[0], k1 = k[1], k2 = k[2], k3 = k[3];

    uint32_t delta = 0x9E3779B9;
    uint32_t sum = delta * 32;  // 0xC6EF3720，加密结束时的sum值

    for (int i = 0; i < 32; i++) {
        // 解密顺序和加密完全相反：
        // 加密最后一步是更新 v1，所以解密第一步要还原 v1
        v1 -= ((v0 << 4) + k2) ^ (v0 + sum) ^ ((v0 >> 5) + k3);
        v0 -= ((v1 << 4) + k0) ^ (v1 + sum) ^ ((v1 >> 5) + k1);
        sum -= delta;  // 逆向递减
    }

    v[0] = v0;
    v[1] = v1;
}
```

## TIPS：

**Q1：明文长度不是8字节的整数倍怎么办？**

**A：** TEA算法本身不处理填充，它只加密64位整块。如果明文不足8字节，调用者必须在加密之前手动补位。

**PKCS#7填充：** 缺几个字节就补几个0x0?。例如缺3字节就补0x03 0x03 0x03。如果明文刚好8字节，必须额外补满一整块0x08 x8

**零填充（CTF常见）：** 直接用0x00补满剩余位，逆向时如果看到加密前有memset清零，请考虑零填充

**Q2：为什么我手算的拆分结果和Python跑出来的不一样？**

**A：** 因为x86/x64电脑内存是小端序（低位字节在前）。

例如明文`0x0123456789ABCDEF`，你肉眼看是`01 23 45 67 89 AB CD EF`。但在小端序机器上，uint32_t实际存储是：

`v0`的内存字节：`67 45 23 01`（逻辑值`0x01234567`）

`v1`的内存字节：`EF CD AB 89`（逻辑值`0x89ABCDEF`）

**Q3:**写解密脚本怎么处理PKCS#7填充？怎么处理端序问题?

**A:**端序问题可以通过查询程序端序，如果是小端序，人肉反过来就行

**PKCS#7 填充移除**

**加密时：** 缺 n 个字节，就在末尾补 n 个 n（把“缺了几个”这个数字，当值填进去）

**解密时：** 看最后一个字节的值（就是那个 n），末尾这 n 个字节肯定全都是 n，直接切掉它们就行

**先验证：** 末尾 n 个字节是否全部等于 n，再进行删除

```c
/**
 * PKCS#7 去填充（严格校验）
 * @param input       填充后的数据
 * @param input_len   填充后的长度
 * @param block_size  块大小
 * @param output_len  输出原始数据长度
 * @return 0 成功，-1 填充非法或参数错误
 */
int pkcs7_unpad(const uint8_t *input, size_t input_len,
                size_t block_size, size_t *output_len)
{
    if (block_size == 0 || block_size > 255)
        return -1;
    if (input == NULL || output_len == NULL)
        return -1;
    if (input_len == 0 || input_len % block_size != 0)//检查输入数据的长度是否是块大小（block_size）的整数倍
        return -1;

    uint8_t pad_len = input[input_len - 1];

    // 填充长度必须在 1 ~ block_size 之间
    if (pad_len < 1 || pad_len > block_size)
        return -1;

    // 检查最后 pad_len 个字节是否都等于 pad_len
    for (size_t i = input_len - pad_len; i < input_len; i++) {
        if (input[i] != pad_len) {
            return -1;  // 填充格式错误
        }
    }

    *output_len = input_len - pad_len;
    return 0;
}
```

**Q_Q3:**对于一个TEA加密单位也就是8字节，假如是前7字节任意，最后一个字节空的情况和最后一个字节恰是0x1的情况怎么区分，怎么分出是填充还是原始数据？

**A:**标准 PKCS#7 规定“总是填充”，即使明文长度已经是块大小的整数倍，也会额外补一个完整块

**情况 1：原始 7 字节数据**

```text
原始：     41 42 43 44 45 46 47
填充后：   41 42 43 44 45 46 47 01
```

最后一个字节是 `0x01`，去填充时检查最后 1 个字节等于 `0x01`，合法，去掉 1 字节，得到 7 字节原始数据。

**情况 2：原始 8 字节数据，最后一个字节恰好是 0x01**

```text
原始：     41 42 43 44 45 46 47 01
填充后：   41 42 43 44 45 46 47 01 08 08 08 08 08 08 08 08
```

因为原始长度 8 已经是块大小整数倍，PKCS#7 会补一个完整块，最后一块是 8 个 `0x08`
